# 需手動處理的步驟

# 📍 3-1 旋轉影片預處理

這部分僅針對「旋轉點」的影片進行處理，以確保轉彎方向與直線路段能順暢銜接。

### 3-1-1：判斷是否需要倒轉影片

- **說明**：需要判斷哪些旋轉點需要倒轉，以符合路徑前進方向。
- **範例**：從 `直線A_順向` 走到 `直線B_順向` 時，過程中會經過 `旋轉點B`。需要確認原始拍攝的 `旋轉點B` 的旋轉方向，是否能銜接這兩條直線路段。

### 3-1-2：擷取精確的旋轉片段

- **說明**：需要判斷並擷取旋轉影片的特定片段（`第 X frame` ~ `第 Y frame`）。
- **範例**：原本的旋轉點影片可能是原地繞一整圈，需要找出並擷取能「剛剛好銜接」上一條直線與下一條直線的片段。

## 📍 3-5 最佳影片節點 (Node) 數量設定

- **說明**：需先決定每個路徑要有多少個 Node，再將最佳影片平均下取樣或線性內插到指定的 Node 數，以符合現實距離與地圖像素 (Pixel) 的比例，步驟如下：
    1. **計算像素距離**：拿未來測試場景的室內地圖（具有比例尺的地圖），計算每個轉彎點之間的 pixel 歐式距離（即每段直線路段的長度）。
    2. **查看現有 Node 數**：查詢各路段最佳影片 `.npy` 檔目前的 frame 數（即 Node 數）。
    > 執行：`python scripts/10_check_npy_shape.py --input "Database\Best_Video\Best_Video_Features"`
    3. **決定目標 Node 數**：詳細推導請參考 `docs/最佳影片的節點數推導過程.txt`。
    4. **實際調整 Node 數**：將最佳影片實際 frame 數，內插或下取樣至指定數量。
    > 執行：`python scripts/11_adjust_best_video_length.py --frames <指定的數字>`

## 📍 4-2 測試影片路徑資訊標註

- **說明**：需觀察已經 resize、downsampling 後的測試影片，並手動紀錄`每段路徑名稱`、`該路段frame數`、`累積總 frame 數`。

## 📍 4-4 LSTM 訓練集預處理

### 4-4-1-2：紀錄各訓練影片的路徑資訊

- **說明**：在 `Database\Data\Full Path Tensor` 中存放的是未來要訓練 LSTM 的影片的 `.npy` 檔，需要針對**每一個 `.npy` 檔**，手動紀錄`每段路徑名稱`、`該路段frame數`、`累積總 frame 數`，並存成對應的 `.txt` 檔。
- **命名規則**：若有一個 `4944.npy`，就必須建立一個 `4944_video_information.txt`。
- **內容格式範例**：

    ```
    [直線A_順向, 90, 90]
    [旋轉B, 56, 146]
    [直線B_順向, 34, 180]
    [旋轉C, 46, 226]
    [直線C_順向, 47, 273]
    [旋轉E, 48, 321]
    [直線D_順向, 29, 350]
    ```


### 4-4-1-3：訓練集檔案列表

- **說明**：在上一個步驟完成後，需要建立一個總表來紀錄所有參與 LSTM 訓練的**`檔案名稱`**及其`總 frame 數`，以方便程式自動打包訓練集。
- **輸出位置**：`Database\Data\Full Path Tensor\Full_Path_tensor_info.txt`
- **內容格式範例** `[檔名, 該檔案總 frame 數]`：

    ```
    [IMG_4942, 370]
    [IMG_4944, 350]
    [IMG_4945, 360]
    [IMG_4946, 360]
    [IMG_4948, 360]
    [IMG_4949, 350]
    ```

- **說明**：在連接 Graph 時，需將不同路徑的最佳影片拿出來逐個 frame 檢視，人工決定「某個路段的哪個 frame」最適合連接到「下一個路段的哪個 frame」。
