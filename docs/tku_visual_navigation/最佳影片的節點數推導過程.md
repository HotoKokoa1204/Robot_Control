# 最佳影片 (Optimal Video) 節點數推導過程

本文件說明如何將各個「直線」路徑的 Node 數（即最佳影片的 frame 數）進行線性內插或下取樣，使其與實際室內地圖的 Pixel 歐式距離保持一致比例。這樣做的目的是確保虛擬地圖中「現實物理距離」與「節點數量」的對應關係保持合理。

---

## 📍 1. 旋轉點 (路口) 的 Pixel 座標定義

以下為基於 `map.png` 平面圖，各個旋轉點所對應的座標位置：

```python
pts = [
    (1137, 902 - 560), # 旋轉點 A
    (880,  902 - 590), # 旋轉點 B
    (880,  902 - 483), # 旋轉點 C
    (651,  902 - 463), # 旋轉點 E
    (664,  902 - 580), # 旋轉點 D
    (651,  902 - 463), # 旋轉點 E (與上同)
    (214,  902 - 443), # 旋轉點 G
    (794,  902 - 294), # 旋轉點 L
    (880,  902 - 483), # 旋轉點 C (與上同)
    (1639, 902 - 483)  # 旋轉點 K
]
```

---

## 📏 2. 路段 Pixel 距離與目標 Node 數換算

計算兩點間的 Pixel 距離後，將該距離**除以 2**（此比例係數可視需求自行調整），所得的結果即為該路段應具備的 **目標 Node 數量（Best_Video 的 frame 數）**。

| 路徑名稱 | 起迄點 | 原始 Pixel 距離 | 換算計算 (除以 2) | 目標 Node 數 (四捨五入) |
| :--- | :--- | :--- | :--- | :--- |
| **直線A** | A點 ➜ B點 | `258.75` | `129.37` | **130** |
| **直線B** | B點 ➜ C點 | `107.00` | `53.50` | **54** |
| **直線C** | C點 ➜ E點 | `229.87` | `114.93` | **115** |
| **直線D** | E點 ➜ D點 | `117.72` | `58.86` | **59** |
| **直線D (逆向)**| D點 ➜ E點 | `117.72` | `58.86` | **59** |
| **直線E** | E點 ➜ G點 | `437.46` | `218.73` | **219** |
| **直線F** | G點 ➜ L點 | `598.83` | `299.41` | **299** |
| **直線G** | L點 ➜ C點 | `207.65` | `103.82` | **104** |
| **直線H** | C點 ➜ K點 | `759.00` | `379.50` | **380** |

> 📊 **統計：** 全場域總計涵蓋 **2833.99** 個 Pixel 距離。

---

## ⚙️ 3. 執行線性內插 (Linear Interpolation)

若原始產出的 `Best_Video` 無法滿足上述算出的目標 Node 數，系統必須使用線性內插或均勻下取樣的方式，對特徵陣列與影片進行長度調整。

### 實際需調整範例：
*   **直線A**：原始 `111` 幀 ➔ 需提升至 **`130`** 幀
*   **直線B**：原始 `20`  幀 ➔ 需提升至 **`54`**  幀
*   **直線C**：原始 `51`  幀 ➔ 需提升至 **`115`** 幀
*   **直線D**：原始 `37`  幀 ➔ 需提升至 **`59`**  幀

> 💡 **操作提示：**
> 取得上述目標幀數後，您可以執行 `python scripts/tku/visual_navigation_system/11_adjust_best_video_length.py --frames <目標數字>` 來完成該路徑的 Node 數量對齊。
